# Contributing to the docs

The easiest way to contribute to the documentation is sending an email to [support@pretix.eu](mailto:support@pretix.eu).

Did you spot a typo?
Did you discover a formatting error?
Did you stumble over outdated information?
Did you notice that something is missing?
Do you have suggestions how to improve the documentation?
Do you want to add a new article?
Do you want to add a translation?

[Send us an email](mailto:support@pretix.eu).

Alternatively, if you have an account on GitHub, you can browse to the repo and [open an issue](https://github.com/pretix/pretix-docs/issues) there.

## Adhere to our Code of Conduct

Before you contribute to pretix itself or its documentation, read our [code of conduct](https://docs.pretix.eu/dev/development/contribution/codeofconduct.html).
Adhere to this code of conduct while making contributions.

## Adhere to our AI-assisted contribution policy

Before you contribute to pretix itself or its documentation, read our [AI-assisted contribution policy](https://docs.pretix.eu/dev/development/contribution/ai.html).

This policy focuses on code contributions, but it also applies to text contributions.
When applied to the pretix documentation, the policy entails the following:

You, as the human-in-the-loop, must understand all of the text you contribute.
Thus, you need to verify that the LLM output is factually accurate and not misleading.

The pretix documentation is a primary source.
If a user prompts an LLM about pretix, then the LLM's will base its output on this documentation, at least in part.
If a user prompts the LLM about aspects of pretix that this documentation does not cover yet, then it is highly unlikely that the LLM's output will be accurate or helpful.
Thus, human research and critical editing are absolutely imperative to improve and expand this documentation.
